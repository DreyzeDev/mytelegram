# Инструкция по запуску сервера MyTelegram

В этом документе описаны точные шаги, которые я лично выполнял для успешного локального запуска и настройки сервера MyTelegram (со всеми исправлениями для подключения и обхода СМС).

## 1. Подготовка окружения
Для работы сервера потребуется установленный **Docker** (и Docker Compose). Все компоненты запускаются через Docker, что позволяет избежать проблем с зависимостями на хост-машине (Windows/Linux).

## 2. Ключевые исправления перед запуском

В процессе настройки мы столкнулись с двумя главными проблемами, которые нужно было решить:
1. **Бесконечное подключение (Handshake) в клиенте.** Сервер `gateway` кеширует ключи шифрования в папке `tdata`. Если ключи сервера и базы данных рассинхронизируются (например, при пересоздании БД), клиент не сможет подключиться. 
   * **Решение:** В файле `docker/compose/docker-compose.yml` мы убрали монтирование локального тома для папки `/app/tdata` у сервиса `gateway`. Теперь при пересоздании контейнера папка `tdata` создается с нуля и генерирует свежие валидные ключи.

2. **Вход без реального номера (Тестовые аккаунты).** По умолчанию сервер строго проверяет длину номера и код страны.
   * **Решение:** Мы внесли изменения в исходный код. В файле `source/src/MyTelegram.Messenger/Handlers/LatestLayer/Auth/SendCodeHandler.cs` внутри метода `CheckPhoneNumber` мы добавили код, пропускающий проверку для номеров, начинающихся с `+999`:
     ```csharp
     if (phoneNumber.StartsWith("999") || phoneNumber.StartsWith("+999"))
     {
         return;
     }
     ```

## 3. Сборка обновленных Docker-образов
Поскольку мы изменили исходный код C#, нам нужно пересобрать образы, чтобы изменения вступили в силу. Открой терминал в корне проекта (где лежит папка `source`) и выполни следующие команды:

```bash
# Сборка CommandServer (обрабатывает команды, включая логин)
docker build -t mytelegram/mytelegram-messenger-command-server:latest -f source/src/MyTelegram.Messenger.CommandServer/Dockerfile source/

# Сборка AuthServer (также использует обновленную логику)
docker build -t mytelegram/mytelegram-auth-server:latest -f source/src/MyTelegram.AuthServer/Dockerfile source/
```
*Важно: Теги образов (`mytelegram/`) должны в точности совпадать с тем, что указано в `.env` файле для переменной `MyTelegramRegistry`.*

## 4. Настройка файла .env
Перейди в папку `docker/compose/` и убедись, что файл `.env` настроен корректно. Основные моменты:
* `MyTelegramRegistry=mytelegram` (чтобы docker-compose использовал наши локальные собранные образы).
* `App__FixedVerifyCode=22222` (именно этот код будет подходить ко всем СМС).

## 5. Запуск сервера
Находясь в папке `docker/compose/`, запусти все контейнеры в фоновом режиме:
```bash
docker-compose up -d
```
*Если образы обновлялись, можно добавить флаг `--force-recreate`, чтобы Docker принудительно пересоздал контейнеры с новым кодом.*

## 6. Как проверить работу
1. Открой клиент Telegram (например, Telegram Desktop).
2. Введи номер телефона в формате: `+9991234567`.
   *(Если клиент пишет "Invalid Country Code" или "Нет такой страны" - просто проигнорируй это и нажми Next/Далее. Сервер теперь настроен принимать такие номера).*
3. Введи код подтверждения: `22222`.
4. Готово! Ты авторизован.

## Решение частых проблем
* **Клиент долго грузится и не подключается (Connecting...):** Останови контейнеры (`docker-compose down`), убедись, что для сервиса `gateway` в `docker-compose.yml` не примонтирована папка `tdata`, и запусти контейнеры заново.
* **Сервер падает или не пускает номер `+999`:** Убедись, что образы были успешно собраны (пункт 3) и теги в точности совпадают с переменными из `.env`.
